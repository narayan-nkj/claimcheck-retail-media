# Ethical Visibility, GitHub Stars/Views, and lablab Hearts Plan

## Objective

Increase legitimate discovery and engagement for ClaimCheck while protecting hackathon integrity, team privacy, and platform rules.

## What to measure

Record these as observed metrics with timestamp and URL:

- GitHub repository stars.
- GitHub repository views and unique visitors, where GitHub exposes them.
- GitHub forks, issues, discussions, pull requests, and README traffic where available.
- Demo application visits and successful demo sessions.
- lablab project-page hearts and page views where the platform exposes them.
- Video views and completion rate where the hosting platform exposes them.
- Referrals by channel using tagged links or a simple campaign log.

Do not use stars, views, or hearts as proof of technical quality, judge score, AMD eligibility, or user adoption.

## Legitimate activities

- Make the public GitHub repository easy to understand and run from a clean environment.
- Add a concise README with the problem, intended user, architecture, AMD workload, screenshots, demo URL, video, evaluation limits, license, and contribution guidance.
- Publish a short, honest demo showing the claim-to-evidence chain, a blocked/stale case, audit record, and AMD proof.
- Share the project with the team’s real networks, hackathon community, mentors, relevant developer groups, and interested commerce/AI communities where self-promotion is allowed.
- Ask for useful feedback, not guaranteed stars or hearts.
- Share changelogs and progress updates that point to the public repository and demo.
- Respond to legitimate questions and issues.
- Use a single transparent project URL and campaign log.

## Prohibited activities

No bought engagement, bots, fake accounts, click farms, vote exchanges, engagement pods, mass unsolicited messages, misleading claims, duplicate submissions, or activity designed to manipulate lablab judging or GitHub metrics. Do not ask people to star or heart without giving them a chance to inspect the project, and do not represent engagement as endorsement of accuracy or compliance.

## Acceptance criteria

- README, demo, repository, and lablab page are publicly reachable.
- Every outreach message is truthful and identifies the project.
- Campaign activity is logged with channel, date, owner, URL, and outcome.
- Metrics are captured from platform analytics without scraping private data or violating terms.
- No activity is a release blocker if it risks rule non-compliance.
- Product, AMD proof, reproducibility, and submission quality remain higher priority than engagement counts.
