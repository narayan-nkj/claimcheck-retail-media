# Six-Day ACT III Build and Submission Plan

Use the live form and organizer guidance as the authority if dates or cutoff details differ.

| Day | Hackathon outcome | Hard evidence |
|---|---|---|
| Day 1 | Team/track/eligibility check, AMD smoke test, claim classes and synthetic schema frozen | AMD pass or escalated blocker; 20–30-case matrix |
| Day 2 | Deterministic matcher, claim extraction boundary, PASS/REVIEW/BLOCK flow, audit artifact | Fixture cases produce expected decisions |
| Day 3 | AMD workload integrated into the demonstrated product path; freshness/conflict handling and operator view | AMD pass/fail/review recording |
| Day 4 | Evaluation, error analysis, usability test, README, license and secret review | Metrics, known limitations, replay instructions |
| Day 5 | Feature freeze; demo/video, slides, cover image, public repo, app URL, submission fields | Complete release candidate |
| Day 6 | Early submission, confirmation capture, no risky new integrations | Submission receipt and frozen backup |

Explore optional partner work only after the AMD core path and submission-critical artifacts pass.
