ClaimCheck Architectural Flow

The ClaimCheck deterministic pipeline ingests four evidence inputs: Ad Copy, Catalog and Pricing data, Warehouse Inventory, and Carrier Transit SLAs. Data passes into the central processing pipeline starting with Ingestion and Security Sanitization, progressing through Structured Claim Extraction (accelerated by AMD ROCm), Multi-Source Ground Truth Corroboration, and a sub-1.2 millisecond Deterministic Policy Gate, before reaching Cryptographic Tri-State Verdict sealing. Outbound verified outcomes produce Verified Allowed claims, Blocked claims, prioritized Human Review queues, and bit-for-bit Chained Merkle Audit Ledgers.

01 // Ingestion & Sanitization

ZERO-RETENTION

Programmatic ad copy, merchant dashboard submissions, and API webhooks are immediately sanitized. Bearer tokens, API keys, credentials, customer emails, credit cards, and SSNs are permanently redacted prior to model inference or storage.

PII Redaction: Deterministic Regex • < 0.5ms

02 // ROCm™ Claim Span Extraction

AMD ROCm 6.2

Open-weights Llama-3.1-8B-Instruct accelerated on AMD Instinct™ MI300X with CPU fallback. Extracts exact character spans and classifies claims across Pricing, Availability, Shipping Promise, and Product Attribute categories.

Acceleration: ROCm™ • CPU Fallback Active

03 // Multi-Source Ground Truth

FRESHNESS SYNC

Resolves Target Product SKUs against master merchant catalogs and real-time inventory feeds. Enforces strict freshness validity intervals so pricing baseline, stock quantities, and carrier transit SLAs reflect actual warehouse reality.

Corroboration: Multi-Warehouse • Precedence Engine

04 // Deterministic Policy Gate

FTC 16 CFR § 233

Sub-1.2ms mathematical evaluation guarding against false strikethroughs, phantom stockout barriers, and carrier transit mismatches. If any mandatory claim fails or evidence is missing, the system fails closed.

Policy Latency: < 1.2ms • Fail-Closed Security

05 // Role-Based Human Review

DUTY SEPARATION

High-risk contradictions and feed discrepancies route to prioritized review queues. Strict separation of duties prevents junior operators from overriding factual blocks while authorizing senior compliance officers.

Governance: DEC-010 • Priority 95 SLA

06 // Tamper-Evident Merkle Ledger

SHA-256 CHAIN

Every verification check, operator override, and re-evaluation is committed into a forward-chained Merkle audit stream. Each block seals the previous block's SHA-256 digest, providing mathematical non-repudiation and 1-click historical replay.

Auditability: Bit-for-Bit Replay • Immutable
